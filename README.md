# Master prompt / продуктовая стратегия
## Neeklo AI Operations Platform

> **Назначение документа:** передать этот файл AI-агенту, продуктовой команде или coding-агенту как единое техническое и продуктовое задание на создание premium mobile-first веб-сервиса.
>
> **Режим работы исполнителя:** думай как founder уровня $1M ARR SaaS, CPO премиального consumer/business продукта, UX-дизайнер и сильный full-stack архитектор. Не создавай «онлайн-курс». Создай полезную AI operating system для предпринимателей.

# 1. Главная задача

Создай премиальный mobile-first веб-сервис **Neeklo AI Operations Platform** — подписочную платформу для русскоязычных предпринимателей, руководителей, маркетологов, РОПов, владельцев агентств и креаторов.

Платформа помогает человеку пройти путь:

```text
Бизнес-проблема → диагностика → подходящий AI-сценарий → понятное обучение → шаблоны → запуск самостоятельно / заказ внедрения → измерение результата
```

Продукт не должен быть энциклопедией «про нейросети» и не должен выглядеть как типичная онлайн-школа с длинными уроками. Его задача — помочь пользователю **найти и внедрить конкретное решение для потери денег, заявок или времени**.

## Core promise

**Перестаньте терять заявки, время и деньги. Найдите подходящий AI-сценарий для вашего бизнеса, поймите его за 10 минут и запустите с готовыми шаблонами.**

## Product category

- AI Operations Platform
- Curated knowledge base
- Scenario library
- Workflow and agent template hub
- Premium learning workspace
- Lead-generation and delivery layer для студии Neeklo

# 2. Стратегическая позиция

## Не создавать

- Общий каталог из тысяч AI-инструментов.
- Курс «всё о нейросетях с нуля».
- Копию ChatGPT, n8n, Notion, Skillbox или маркетплейс фрилансеров.
- Перегруженный кабинет с десятками функций.
- Community-first продукт без ценности до появления сообщества.

## Создавать

Премиальный продукт, где каждая единица контента отвечает на вопрос:

> **Какую рабочую задачу я решу, какой получу результат, сколько это займёт, какие инструменты нужны и что делать прямо сейчас?**

## Дифференциация

Neeklo должен выигрывать по пяти параметрам:

1. **От задачи, а не от инструмента.** Пользователь приходит с болью, не обязан знать названия AI-сервисов.
2. **От теории к действию.** Каждая карточка содержит схему, шаблон, видео, порядок запуска и KPI.
3. **Язык собственника.** Лиды, конверсия, скорость ответа, зарплатный фонд, время, маржа, ошибки — а не абстрактный «AI transformation».
4. **Премиальная редактура.** Мало материалов, но каждый действительно полезен, красиво упакован и регулярно обновляется.
5. **Путь к внедрению.** Пользователь может учиться сам, тестировать агента или передать задачу Neeklo/исполнителю.

# 3. Целевая аудитория и Jobs-to-be-Done

## Сегмент A — владелец малого/среднего бизнеса

**Контекст:** есть 5–100 сотрудников, обращения клиентов, процессы, CRM, таблицы, хаос в коммуникациях. Не хочет становиться техническим специалистом.

**Job:** «Помоги мне понять, где AI даст деньги или освободит команду, и внедрить это без риска». 

**Нужный результат:** shortlist из 3 приоритетных AI-сценариев, понятный ROI и возможность заказать внедрение.

## Сегмент B — руководитель продаж / маркетинга

**Контекст:** отвечает за заявки, скорость ответа, качество лидов, КП, follow-up, рекламу и контент.

**Job:** «Помоги мне обработать больше лидов и ускорить работу команды без найма ещё двух людей». 

**Нужный результат:** рабочий сценарий AI SDR / lead qualification / proposal generator / content workflow.

## Сегмент C — операционный руководитель

**Контекст:** тонет в документах, статусах, ручной передаче задач, отчётах, контроле качества.

**Job:** «Убери повторяющуюся рутину и сделай процесс прозрачным». 

**Нужный результат:** knowledge base, document workflow, executive digest, procurement/support agent.

## Сегмент D — агентство, студия, консультант

**Контекст:** регулярно делает брифы, коммерческие предложения, отчёты, исследования, delivery, контент.

**Job:** «Сделай мою экспертизу воспроизводимой и ускорь коммерческий/проектный контур». 

**Нужный результат:** AI Knowledge & Proposal System.

## Сегмент E — креатор / фрилансер / начинающий AI-оператор

**Контекст:** хочет работать эффективнее, предоставлять новые услуги, делать контент и MVP.

**Job:** «Дай мне понятные практики, чтобы делать результат с AI, а не смотреть бесконечные ролики». 

**Нужный результат:** трек обучения, библиотека промптов, вайб-кодинг, шаблоны услуг и портфолио.

# 4. Продуктовая модель

## North Star Metric

**Число пользователей, которые за 7 дней выбрали сценарий, сохранили шаблон и выполнили хотя бы один action по внедрению.**

Это называется **Activated Operator**.

## Воронка

```text
Контент / реклама / партнёрство
→ публичный лендинг
→ AI-аудит (квиз)
→ персональная карта потерь + 3 сценария
→ регистрация
→ пробный premium-доступ / оплата
→ первое сохранённое решение
→ использование шаблона / запуск демо
→ запрос аудита или внедрения
→ клиент Neeklo / подписчик
```

## Монетизация

### Free
- AI-аудит.
- 5 открытых карточек решений.
- 3 базовых урока.
- Weekly AI Radar.
- Сохранение 1 решения.

### Solo — ориентир 1 490–1 990 ₽/месяц
- Вся библиотека.
- Шаблоны и чек-листы.
- Треки обучения.
- Сохранённые решения и личные проекты.
- Новые материалы и weekly digest.

### Business — ориентир 5 900–9 900 ₽/месяц
- 3–10 пользователей в рабочем пространстве.
- Командные коллекции.
- ROI-калькулятор.
- Приоритетные разборы.
- AI-наставник / внутренний Q&A.
- Ранний доступ к демо-агентам.

### Implementation
- Платный AI-аудит.
- Проектирование процесса.
- Внедрение и интеграции.
- Поддержка и оптимизация.

**Правило:** платформа — не отдельный side-project. Это media + product + воронка в high-ticket внедрения.

# 5. Информационная архитектура

## Основная навигация (mobile bottom navigation)

1. **Главная**
2. **Решения**
3. **Учиться**
4. **Агенты**
5. **Профиль**

На desktop: sidebar с теми же разделами и быстрым поиском.

## Разделы

### 5.1 Главная — персональный операционный dashboard

Показывает:
- персональное приветствие;
- главный вопрос: «Что вы хотите улучшить сегодня?»;
- быстрые входы: Лиды, Продажи, Контент, Документы, Поддержка, Отчёты, Вайб-кодинг;
- «Продолжить мой путь»;
- 3 рекомендованных сценария;
- новая проверенная практика недели;
- progress ring: изучено / сохранено / внедрено;
- CTA: «Пройти AI-аудит».

### 5.2 Решения — core product

Каталог не инструментов, а бизнес-сценариев.

Фильтры:
- Роль: собственник / РОП / маркетолог / операционный руководитель / агентство / креатор.
- Ниша: клиники / онлайн-школы / недвижимость / агентства / производство / дистрибуция / Avito / услуги / другое.
- Функция: маркетинг / продажи / support / operations / финансы / закупки / знания / контент.
- Сложность: старт / уверенный / технический.
- Время запуска: <1 часа / 1 день / 1 неделя / проект.
- Эффект: экономия времени / лиды / качество / контроль / выручка.

### 5.3 Учиться

Состоит из коротких, практических треков:

- AI с нуля для собственника.
- Как правильно ставить задачи AI-агентам.
- AI для продаж и обработки заявок.
- AI для маркетинга и контента.
- AI для базы знаний и документов.
- Вайб-кодинг: сайт, лендинг, MVP, internal tools.
- AI-оператор: как запускать сценарии для клиентов.

Формат урока:
- 5–12 минут видео;
- краткий текст-конспект;
- «зачем это бизнесу»;
- один action item;
- шаблон;
- мини-проверка;
- кнопка «применить в моём проекте».

### 5.4 Агенты

В MVP это **витрина демо-агентов**, не полноценный конкурент конструкторов агентов.

Примеры:
- AI-аналитик бизнес-процесса.
- AI-помощник по постановке задач.
- AI-аудитор входящих лидов.
- AI-генератор коммерческого предложения.
- AI-редактор базы знаний.
- AI-контент-стратег.

Для каждого агента:
- что он делает;
- кому подходит;
- ограничения;
- тестовый чат на лимитированном наборе функций;
- кнопка «сохранить сценарий»;
- CTA «настроить под мой бизнес».

### 5.5 Профиль

- Роль, ниша, размер команды, стек.
- Сохранённые решения.
- Мои проекты.
- Прогресс обучения.
- Подписка и биллинг.
- Уведомления.
- Настройки данных и интеграций.

# 7. Ключевые пользовательские сценарии

## Сценарий 1: собственник приходит с болью

1. Открывает лендинг.
2. Нажимает «Найти AI-решение».
3. Проходит квиз из 6–8 вопросов.
4. Получает короткий результат: главная зона потерь + 3 рекомендуемых сценария.
5. Регистрируется, чтобы сохранить результат.
6. Открывает карточку решения.
7. Смотрит 7-минутный разбор.
8. Забирает шаблон ТЗ и считает потенциальный эффект.
9. Выбирает: сделать самостоятельно / заказать аудит / внедрить с Neeklo.

## Сценарий 2: маркетолог ищет конкретный шаблон

1. Вводит в поиск: «Как быстро обрабатывать заявки из Telegram?»
2. Видит решение AI Lead Recovery System.
3. Открывает материалы, шаблон и инструкцию.
4. Нажимает «Сохранить в проект».
5. Получает задачу на сегодня: «Подключите один канал входящих и задайте правила квалификации».
6. Через 3 дня получает reminder: «Удалось проверить сценарий?»

## Сценарий 3: пользователь хочет использовать агента

1. Открывает «Агенты».
2. Выбирает AI-аналитика процессов.
3. Заполняет краткий бриф.
4. Получает структурированную карту: процесс / потеря / решение / приоритет.
5. Сохраняет результат в «Мой проект».
6. Видит CTA на шаблон workflow или консультацию.

## Сценарий 4: пользователь переходит в high-ticket услугу

1. Использовал 2–3 карточки и сохранил решение.
2. Видит: «Нужна настройка под ваш бизнес?».
3. Выбирает пакет: экспресс-аудит / дизайн процесса / внедрение.
4. Заполняет brief.
5. Лид автоматически попадает в CRM Neeklo.
6. Менеджер получает summary, контекст и рекомендованный следующий шаг.

# 8. Дизайн-направление

## Ощущение

Платформа должна восприниматься как:

- premium editorial product;
- спокойный и умный digital workspace;
- «Apple-level clarity + Linear-level precision + Notion-level utility»;
- не глянцевая крипто-страница и не дешёвая LMS;
- визуальная система для серьёзного предпринимателя.

## Визуальные принципы

- Много негативного пространства.
- Крупная аккуратная типографика.
- Светлая тёплая база: off-white / graphite / soft grey.
- Один насыщенный акцентный цвет: electric lime, cobalt или deep violet — выбрать один и использовать экономно.
- Мягкие градиенты только в hero и premium state.
- Тонкие бордеры, скругления 16–24 px, лёгкая глубина.
- Карточки должны быть «воздушными», не коробками внутри коробок.
- Контент важнее декоративных иллюстраций.
- Анимации: короткие, тактильные, 150–220 ms; без перегруза.

## Mobile-first правила

- Минимум 44×44 px для tap targets.
- Bottom navigation всегда доступна.
- Поиск и фильтры открываются в bottom sheet.
- Длинные материалы разбиты на короткие блоки.
- Sticky CTA в нижней зоне на карточке решения.
- Состояние прогресса всегда понятно.
- Платформа должна ощущаться как нативное приложение: PWA, быстрые transition, skeleton loaders, offline сохранение лёгких данных.

## Accessibility

- Контраст не ниже WCAG AA.
- Полная навигация клавиатурой на desktop.
- Поддержка screen-reader labels.
- Не кодировать смысл только цветом.
- Подписи к видео / транскрипт.

# 9. Технологическая архитектура

## Рекомендуемый стек

Используй современный production-ready web stack:

- **Frontend:** Next.js (App Router), TypeScript, React.
- **UI:** Tailwind CSS + качественная локальная design system; shadcn/ui можно использовать как основу, но сильно кастомизировать.
- **Backend / DB / Auth:** Supabase (Postgres, Auth, Storage, Row-Level Security) либо эквивалентная managed Postgres-архитектура.
- **ORM:** Drizzle или Prisma.
- **Payments:** abstraction layer. Для RU — подключаемый провайдер оплаты; для international — Stripe/аналог. Не хардкодить одного поставщика.
- **Content:** MDX / headless CMS с versioning. Контент должен редактироваться без redeploy.
- **Search:** Postgres full-text для MVP, затем Meilisearch/Algolia по мере роста.
- **Video:** защищённый video hosting / storage с подписанными URL; у каждого урока есть транскрипт.
- **Analytics:** PostHog или аналог с event taxonomy.
- **Email / notifications:** Resend / Unisender / аналог через abstraction.
- **Error monitoring:** Sentry.
- **Feature flags:** PostHog / LaunchDarkly / простая server-side implementation.

## Важные архитектурные принципы

- Mobile performance прежде всего: LCP < 2.5s на ключевых экранах при нормальном соединении.
- Public content SEO-friendly, private content закрыт от индексации.
- Все роли и доступы серверно проверяются; не доверять клиенту.
- Контент и сущности имеют status: draft / review / published / archived.
- Нужны audit logs для admin-действий.
- Интеграции и API-ключи хранятся encrypted at rest; секреты не выдаются клиенту.
- Агентные действия по умолчанию не совершают irreversible actions без отдельного подтверждения пользователя.

# 11. AI-аудит: квиз как главный activation engine

## Цель

Не просто собрать email, а дать человеку полезный первичный результат и понять его intent.

## Вопросы (6–8 шагов)

1. Какая ваша роль?
2. Какая ниша / тип бизнеса?
3. Размер команды?
4. Где сейчас больше всего ручной рутины?
5. Какая проблема болит сильнее: лиды / продажи / контент / документы / поддержка / отчёты / знания?
6. Какие инструменты уже используете?
7. Насколько готовы внедрять: сам / с командой / нужен исполнитель?
8. Что будет считаться успехом через 30 дней?

## Результат

Покажи:
- **ваша главная точка потери**;
- 3 подходящих сценария;
- потенциальный эффект в логике «время / лиды / контроль»;
- первый шаг на 20–30 минут;
- CTA: «Сохранить карту и получить шаблоны».

Важно: не рисовать фиктивную финансовую экономию. Если нет достаточных входных данных, использовать формулировки «гипотеза эффекта» и просить заполнить метрики для более точной оценки.

# 12. Контент-операционная система

## Форматы контента

- Solution card — основной premium-юнит.
- Практический урок.
- Template pack.
- Case study.
- Tool guide.
- AI Radar update.
- Framework / методология.
- Decision tree.
- Benchmark / checklist.

## Редакционный процесс

```text
Идея / сигнал рынка
→ исследование источников
→ авторская рамка Neeklo
→ сценарий решения
→ редактура и fact-check
→ видео + шаблоны
→ review
→ публикация
→ рассылка / продуктовая рекомендация
→ обновление по feedback и новым инструментам
```

## Content quality score

Не публиковать материал, если он не отвечает минимум на 6 вопросов:

1. Для кого это?
2. Какая проблема?
3. Какой конкретный результат?
4. Что нужно подготовить?
5. Какие действия совершить?
6. Как понять, что сценарий сработал?

## Защита авторских прав

- Не копировать чужие уроки, интерфейсы, закрытые шаблоны или статьи.
- Использовать собственные методологии, видео, схемы, пересказ с аналитикой и ссылки на первоисточник.
- Для внешних источников хранить source URL, дату проверки и редакторский статус.
- Показывать пользователю первоисточник там, где это уместно.
- Для user-generated materials использовать terms of use и подтверждение прав автора.

# 13. AI-агенты внутри продукта: правила

## Принцип

Сначала агент — это полезный guided assistant, а не автономная сущность с неограниченным доступом к данным пользователя.

## Первые агенты

### AI Process Auditor
Вход: описание бизнеса, роли, процессы, боли.

Выход: таблица:
- процесс;
- потери;
- гипотеза AI-решения;
- сложность;
- приоритет;
- данные/инструменты для запуска;
- следующий шаг.

### AI Task Architect
Вход: задача пользователя.

Выход: готовая спецификация по формуле:

```text
Роль → цель → контекст → входные данные → действия → ограничения → формат → критерий готовности
```

### AI Proposal Architect
Вход: бриф клиента, услуга, кейсы, условия.

Выход: структура КП, черновик, список уточняющих вопросов, next steps.

### AI Content Strategist
Вход: ниша, аудитория, оффер, цель.

Выход: 30 тем, хуки, сценарии, CTA, контент-рубрики.

## Безопасность агентов

- Ясно показывать пользователю, что вывод агента — черновик/рекомендация.
- Никогда не обещать юридический, медицинский, финансовый или иной профессиональный совет без ограничений.
- Агент не должен отправлять сообщения, менять записи, тратить деньги или выполнять external write-actions без явного user confirmation.
- Логировать запуск, версию промпта, входы, выходы и ошибки.
- Добавить rate limits и abuse prevention.

# 16. Запуск и валидация спроса

## До разработки full product

### Критерии продолжения

```text
- 10+ оплаченных founding members из релевантного трафика;
```

# 18. Definition of Done для MVP

MVP считается готовым только если пользователь с телефона без помощи менеджера способен:

1. Пройти регистрацию.
2. Пройти AI-аудит.
3. Получить релевантные рекомендации.
4. Найти нужный сценарий через поиск/фильтр.
5. Понять кейс менее чем за 5 минут.
6. Посмотреть видео и прочитать текстовую выжимку.
7. Скопировать или скачать шаблон.
8. Сохранить решение в свой проект.
9. Оставить запрос на внедрение.
10. Оплатить/отменить подписку.
11. Получить уведомление о новом релевантном материале.

## Обязательные качества

- Не должно быть пустых экранов без очевидного next action.
- Не должно быть lorem ipsum в production demo.
- У каждой карточки есть понятный outcome, уровень сложности и CTA.
- Mobile UX не является уменьшенной desktop-версией.
- Есть loading, empty, error, permission-denied и offline состояния.
- Есть политика приватности, terms, data deletion flow.
- Закрытый контент реально защищён серверной проверкой доступа.
- Все формы валидируются и имеют понятные ошибки.

# 20. Финальная инструкция исполнителю

Создавай не витрину AI-инструментов, а премиальный продукт принятия решений и внедрения.

Пользователь должен после первого визита подумать:

> «Наконец-то мне не продают очередной хайп про нейросети. Здесь понятно, что именно мне внедрить, зачем это нужно моему бизнесу и как сделать первый шаг сегодня».

При каждом продуктовом решении задавай вопрос:

> **Это помогает пользователю быстрее перейти от проблемы к измеримому действию?**

Если нет — убирай из MVP или переносишь в позднюю фазу.
